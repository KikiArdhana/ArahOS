# ARAH

**Your Personal Life Operating System.** Personal finance, goals, assets, debts, bills, maintenance, and notifications in one premium, mobile-first app. Single owner — no tenants, no sharing. Just you.

Built with Next.js (App Router), TypeScript, TailwindCSS, Supabase, TanStack Query, Zustand, React Hook Form + Zod, Framer Motion, Lucide, and Sonner.

## Features

- **Home** — greeting + live clock, net-worth hero, monthly income/expense, quick stats, menu grid, goal/bill/maintenance previews, recent activity, notification badge, FAB, floating bottom nav
- **Money** — accounts, income/expense transactions with search + filters, transfers, allocations; balances kept in sync by database triggers
- **Goals** — targets, contributions, progress, history, archive, auto-complete with confetti celebration
- **Assets** — net-worth breakdown by category, gain/loss since purchase, archive
- **Debts** — both directions (I owe / they owe me), partial payments, auto-settle, due reminders
- **Bills** — recurring frequencies, mark-paid rolls the due date forward, calendar view, history, reminders
- **Maintenance** — recurring schedules, completion log with cost, auto-reschedule
- **Inbox** — unread / read / archived; reminders generated by a database function
- **Profile** — avatar, name, username, theme (light/dark/system), 6-digit PIN lock (bcrypt-hashed), biometric placeholder, password change, sign out
- **Auth** — Supabase email + password, remember me, password reset, protected routes via middleware, PIN lock screen

## Quick start

```bash
# 1. Install
npm install

# 2. Create a Supabase project at https://supabase.com, then configure env
cp .env.example .env.local
#    → fill NEXT_PUBLIC_SUPABASE_URL and NEXT_PUBLIC_SUPABASE_ANON_KEY

# 3. Apply the database schema
#    Option A: Supabase CLI
supabase link --project-ref <your-ref>
supabase db push
#    Option B: paste supabase/migrations/00000000000001_init.sql into the
#    Supabase Dashboard → SQL Editor and run it.

# 4. (Recommended) In Supabase → Authentication → Providers → Email,
#    disable "Confirm email" so registration signs you in immediately.

# 5. Run
npm run dev
```

Open http://localhost:3000, register your account, create your PIN, done. Optional sample data: run `supabase/seed.sql` **after** registering.

## Deployment (Vercel)

1. Push the repo to GitHub and import it in Vercel — `vercel.json` is included and Next.js is auto-detected.
2. Add the two `NEXT_PUBLIC_SUPABASE_*` environment variables (plus `NEXT_PUBLIC_CURRENCY` / `NEXT_PUBLIC_LOCALE` if you want something other than IDR).
3. In Supabase → Authentication → URL Configuration, set your production URL as the Site URL.
4. Deploy.

Any Node host works too: `npm run build && npm run start`.

## Architecture notes

- **Single owner** — every table carries `user_id` with owner-only RLS policies; the app has exactly one account (yours).
- **Money math lives in the database** — triggers keep account balances, goal progress, debt settlement, and bill/maintenance schedules consistent no matter where writes come from.
- **Reminders** — `generate_due_notifications()` runs once per app session (and optionally daily via `pg_cron`, see `supabase/README.md`).
- **PIN lock** — bcrypt hash stored in `profiles.pin_hash`; unlock state is per browser session.
- **Typography** — Inter ships with the repo; drop `Satoshi-Variable.woff2` into `public/fonts` for the premium display face (see `public/fonts/README.md`).
